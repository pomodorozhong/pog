## Game file formats (as found in the current patch)

Paths below are inside the game folder, `~/Library/Application Support/CrossOver/Bottles/Elden Ring/drive_c/Program Files (x86)/Steam/steamapps/common/ELDEN RING/Game`.

### Archives (`Data0–3`, `DLC`, `sd/sd`, `sd/sd_dlc02`)

- **Index (`.bhd`):** RSA-encrypted in 256-byte blocks; each decrypts to 255 bytes (drop the leading byte).
  - **Keys:** the five public keys are PEM strings inside `eldenring.exe`.
  - **Speed:** the exponents are about 31 bits, so pure-Python decryption takes about 2 minutes for all archives. Decrypted indexes are cached in `.cache/bhd/<name>-<size>-<mtime>.bhd5`.
  - **Picking a key:** each key is tried on the first block only.
- **Index format (BHD5):** bucket count and bucket offset at `0x10`. Each file entry is 40 bytes: `u64 hash, i32 padded size, i32 size (0 = use padded), i64 offset, i64 sha offset, u64 aes offset`.
  - **AES block:** 16-byte key, `i32` range count, then `(i64 start, i64 end)` ranges, decrypted with AES-128-ECB; `-1` marks an unused range.
- **Path hash:** lowercase, `\` → `/`, leading `/`, then `h = h * 0x85 + c` in 64 bits.
- **Archive sizes:** 5,878 to 39,684 files per archive.

### DCX compression

- **Payload:** starts after the `DCA\0` marker + 8. Sizes are big-endian at `0x1C` (uncompressed) and `0x20` (compressed); the algorithm name is at `0x28`.
- **KRAK (Kraken):** every 256 KB block sets the "restart decoder" flag, so each block is self-contained and starts with its own 8 literal bytes. ooz ignores that flag for Kraken and fails on the second block.
  - **Fix:** split the stream at block boundaries and decompress each block alone with `pyooz` (`kraken_decompress` in `er_archive.py`).
  - **Block layout:** 2-byte header, then a 3-byte quantum header holding compressed size − 1 in its low 18 bits. `0x3FFFF` means a memset block, and header flag `0x40` means stored uncompressed.
- **ZSTD:** used by `regulation.bin` since a recent patch.
- **Not decoded:** about 115 tiny files (240–480 bytes, `EVD…` contents) use Oodle decoder type 2, which ooz doesn't support. 3 large, partly encrypted files in Data0 also fail. Nothing we need is among them.
- **Not used:** the original ooz source (github.com/powzix/ooz) is Windows-only. A debug build for x86_64 with shim headers (run under Rosetta) is how the restart issue was found.

### Binders

- **BND4:** the bit-order flag is the byte at `0x0A`; when it is 1, the format byte (`0x31`) must be bit-reversed. Message binders use format `0x74`, which reverses to IDs + names + compression, giving 36-byte file headers.
- **BHF4 + BDT split binders:** used for `menu/hi/00_solo.tpfbhd/.tpfbdt` (icons, 1.4 GB) and `menu/71_maptile.tpfbhd/.tpfbdt` (tiles, 1.26 GB). Entries are read by range, never loaded whole.
- **TPF:** 0x14-byte texture entries; a UTF-16 name flag sits at `0x0E`. The textures are DX10 DDS (BC7), which Pillow decodes.

### Text (FMG)

- **Source file:** `msg/<engus|zhotw>/item_dlc02.msgbnd.dcx` holds every name table: base game, `_dlc01` (Shadow of the Erdtree) and `_dlc02` (placeholder tables with one entry).
- **Format:** version 2 (64-bit). Group table at `0x28`, 16 bytes per group; string offsets are `i64` at the offset stored at `0x18`.
- **Empty tables:** some tables are zero-length files.
- **Placeholders:** names starting with `[ERROR]` are placeholders (47 armor rows); they're filtered out.

### Params (`regulation.bin`)

- **Decryption:** AES-256-CBC with the public key used by SoulsFormats; the first 16 bytes are the IV. It decrypts to ZSTD DCX → BND4 holding 194 `.param` files.
- **Row table:** row count is `u16` at `0x0A`; rows start at `0x40`, 24 bytes each (`i32 id, i32 pad, i64 data offset, i64 name offset`).
- **Field offsets:** computed from soulsmods/Paramdex `ER/Defs/*.xml`. Bitfields of the same base type pack into one unit. Row size is checked against the file.

| Param               | Row size | Fields used (offset)                 |
| ------------------- | -------- | ------------------------------------ |
| EquipParamWeapon    | 664      | `iconId` u16 @190                    |
| EquipParamProtector | 416      | `iconIdM` u16 @166                   |
| EquipParamAccessory | 96       | `iconId` u16 @38                     |
| EquipParamGoods     | 176      | `iconId` u16 @48, `goodsType` u8 @62 |
| EquipParamGem       | 96       | `iconId` u16 @4                      |
| BonfireWarpParam    | 236      | not used yet (fields below)          |

- **Weapon variants:** weapon rows whose ID isn't a multiple of 10,000 are infusion or upgrade variants and are skipped.
- **goodsType counts in the catalog:** 7: 561, 0: 396, 8: 363, 1: 294, 2: 106, 12: 102, 16: 87, 5: 69, 14: 43, 18: 42, 10: 40, 3: 25, 17: 15, 15: 6, 11: 4, 9: 2. The meaning of each value isn't mapped yet.

### Map tiles

- **Tile names:** `MENU_MapTile_M<map>_L<lod>_<x>_<y>_<mask>`; x/y count from the bottom-left (flip y for Leaflet).
- **Maps:** M00 overworld, M01 underground, M10 DLC, M11 DLC underground.
- **Zoom levels:** L0 is full resolution (41×41 tiles of 256 px). L1 (31×31) and L2 (11×11) aren't powers of two, so the extractor builds its own pyramid from L0.
- **Masks:** one bit per map fragment (bit 14 = outside the map).
  - **Picking a variant:** the fully revealed one is named in `menu/71_maptile.mtmskbnd.dcx`, a BND4 of plain XML `.mtmsk` files whose entries read `id = lod*10000 + x*100 + y`, `mask`, `exists`.
  - **What failed:** picking "most bits set", or excluding rare bits, gives scrambled maps.
  - **M11:** has no mask entries; only `00000000` tiles exist.
- **Icons:** `MENU_Knowledge_<iconId:05>.tpf.dcx`, 1024 px, saved as 256 px WebP. 3 referenced icons don't exist.

## Graces and the world-to-map transform (milestone 3 groundwork)

- **`BonfireWarpParam`:** 422 rows.
  - **Fields:** `eventflagId` (discovered), `textId1` (a `place/<id>` in the catalog), `areaNo`, `gridXNo`, `gridZNo`, `posX`, `posY`, `posZ`.
  - **Rows per area:** 60 (overworld): 166, 61 (DLC): 59, 12 (underground): 32, 30: 18, 11: 16, 31: 16, 21: 14, 34: 12, 13: 11, 10: 10, 20: 10, 15: 9, and others.
  - **Examples:** Church of Elleh: area 60, grid (42, 36), flag 76100. The First Step: flag 76101. Gatefront: grid (42, 37), flag 76111.
  - **Overworld grid range:** x 33–54, z 30–58.
- **Fit attempt:** world = `grid * 256 + pos` (meters). Pixel at full resolution = `(worldX − x0) * s`, `(z0 − worldZ) * s`. Each candidate was scored by how many overworld graces land on land (red > blue on the blurred map).
  - **Best:** s = 1.0 (0.99 in the fine search), x0 ≈ 7000–7060, z0 ≈ 16536–16640.
  - **Scores (of 166):**

## App details not in the plan

- **Storage:** documents `map` and `player` at `GET/PUT /api/state/<name>`, in the `env-paths` data folder for `route-of-grace` (override: `ROUTE_OF_GRACE_DATA_DIR`).
- **Game data:** served from `game-data/` by the Vite dev/preview middleware (localhost only). A production build doesn't bundle it.
- **Editor UX:**
  - **Keys:** V select/drag, G grace, J junction, I item pin, E entrance, P draw path, ⌘Z / ⇧⌘Z undo/redo, Delete removes the selection.
  - **Drawing:** starting on empty map creates a junction. Enter ends the path at the last waypoint; Backspace removes a waypoint; Esc cancels. Drawing continues from the node just reached.
  - **Rules:** a path between layers is refused unless the type is waygate.
  - **Labels:** shown from zoom 4.
  - **Item pins:** use a parchment background so dark icons stay visible.
- **Gotchas fixed:**
  - Leaflet lifts `max-width` on marker images, so item icons need an explicit size.
  - The `react-hooks/refs` lint rule forbids writing a ref during render; `MapCanvas` updates its latest-props ref in `useLayoutEffect`.
  - Removing a missing node or path used to add an empty undo step.
- **Testing:**
  - Manual browser tests ran against a scratch data folder via a local `.claude/launch.json` (git-ignored, machine-specific).
  - Unit tests: 7 (editing rules, undo, validation, file store). No end-to-end tests yet.
- **Environment:** Python 3.12 venv via `uv` (`scripts/extract/requirements.txt`: cryptography 50.0.2, pillow 12.3.0, pyooz 0.0.8, zstandard 0.25.0); Node 26 with the stack from the old project plus Leaflet 1.9.4.
